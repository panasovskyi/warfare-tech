# Ingestion: порядок дій

Усі команди — з теки `ingestion`. Шаблонні місця у `<…>` заміни на свої значення.

Є два режими створення чернетки:
- **Автоматичний (звичайний):** команда сама завантажує сторінку, бере з неї текст, дату публікації й адресу головного фото.
- **Ручний:** текст статті ти копіюєш у файл (коли сайт не віддає текст або ховає його за paywall).

## Перед роботою

- Запущені сервери: `server` → `npm run start:dev`, `client` → `npm run dev` (після зміни `client/next.config.ts` клієнт треба перезапустити).
- У `ingestion/.env` є змінні: `ANTHROPIC_API_KEY`, `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`, `API_BASE_URL` (разом із `/api`), `ADMIN_LOGIN`, `ADMIN_PASSWORD` (це має бути адмін: пошта чи логін і пароль із `server/.env`).
- Дозволені джерела (`ALLOWED_SOURCES` у `src/rewriting/sources.ts`): defensenews.com, defence-ua.com, war.gov, airandspaceforces.com, rheinmetall.com, twz.com, breakingdefense.com. Нове джерело: додай рядок «домен без `www.`» → «назва для читача». Defense One свідомо пропущено: його `robots.txt` забороняє GPTBot.
- Заглушку (фірмова картинка, коли в статті немає свого фото) один раз завантажено в Cloudinary як `warfare-tech/fallback`. Змінив `assets/fallback.svg`? Виконай `npm run upload-fallback`.

## Крок 1. Створити чернетку

### Автоматично

```
npm start -- <адреса статті>
npm start -- <адреса статті> <дата публікації YYYY-MM-DD>
npm start -- <адреса статті> <дата публікації YYYY-MM-DD> --image=<посилання на фото>
npm start -- <адреса статті> <дата публікації YYYY-MM-DD> --image=page --credit="Airbus"
```

- Адреса очищується від `utm`, трекінгу й фрагмента (у консолі буде рядок `Link cleaned`).
- **Дублі:** перед платним викликом команда шукає цю статтю серед чернеток у `drafts/` і серед опублікованого на сайті. Знайшла: зупиняється з поясненням. Свідомо створити ще одну чернетку: додай `--force`.
- Дата береться зі сторінки (так для twz.com, defensenews.com, airandspaceforces.com, breakingdefense.com). У консолі буде рядок `Publication date: … (taken from the page)`. **defence-ua.com дати на сторінці не має**, для нього вказуй дату сам. Свою дату завжди можна дописати, вона важливіша за сторінкову.
- Фото: без `--image` стоїть фірмова заглушка, а в попередженні буде адреса фото зі сторінки. `--image=page` завантажує головне фото сторінки на Cloudinary, `--image=<посилання>` завантажує вказане (лише `https`, jpg, png, webp, gif, avif, до 10 МБ). Чуже фото на твоєму Cloudinary це рішення про авторські права, тому за замовчуванням воно вимкнене (див. нижче «Яке фото брати»).
- `--credit="…"` вписує автора фото в поле `photoCredit` (див. нижче). Без реального фото (заглушка) воно ігнорується.
- Роздільник `--` одразу після `start` обов'язковий: без нього `npm` забере `--image=…` собі, і фото загубиться.
- У консолі побачиш `Fetched: <адреса> | "<заголовок сторінки>" | <кількість символів>`. З тексту прибираються меню, реклама, підписи до фото, заголовок і рядок автора на початку; в кінці інколи лишається рядок про автора, модель його ігнорує.

### Українське джерело (Defense Express)

Команда сама це розпізнає: спершу модель **переписує статтю українською**, потім другий виклик **перекладає** результат англійською. Так текст не стає дослівним перекладом оригіналу. Коштує близько 4 центів замість 2.

Поруч із чернеткою з'являється `….uk.md`: український рерайт, у якому жирним (`**…**`) виділено уривки, що збігаються з джерелом. У самій чернетці `overlap:` позначений як «Ukrainian rewrite vs the source», а підсвітки в англійському тексті немає.

**Правиш українську, а не англійську.** Редагуй `….uk.md` (перепиши виділене, прибери зірочки), збережи й запусти:

```
npm run translate
npm run translate -- drafts/<файл чернетки>.uk.md
```

Без шляху береться **найновіша чернетка** (за назвою файлу): якщо в ній немає кирилиці й поруч лежить `.uk.md`, команда перекладає саме його. Це зручно, коли працюєш над однією статтею, але якщо після неї створив іншу, вказуй шлях явно. Команда перекладає заголовок, опис і весь текст з `.uk.md` і **замінює** ними заголовок, опис і текст у англійській чернетці. Теги, фото, підпис фото й нотатки лишаються. Англійський текст, який ти правив руками в `….md`, при цьому замінюється, але його копія зберігається поруч (`….pre-translation.md`). У консолі буде схожість твого українського тексту з джерелом (щоб бачити, чи лишились близькі місця) і попередження перекладу та перевірок.

### Вручну (текст із файлу)

Скопіюй текст у `samples/article1.txt` (старий текст у файлі заміни) і запусти:

```
npm start -- <адреса статті> samples/article1.txt <дата публікації YYYY-MM-DD> --image=<посилання на фото>
npm start -- <адреса статті> samples/article1.txt
```

Дата: формат **YYYY-MM-DD**, наприклад `2026-10-02` (рік-місяць-день). Без дати відносні вирази («last month») лишаться відносними. Фото і дата необов'язкові.

### Для обох режимів

- Один запуск ≈ 2 центи. Одну статтю двічі не запускай: нова чернетка не переносить твоїх правок.
- У консолі з'явиться шлях до чернетки в `drafts/`, розділ, фото, збіги з джерелом, а також рядки `PROBLEM` і `WARNING`.

### Яке фото брати

Фото зі сторінки статті не бери, поки не знаєш, чиє воно і на яких умовах його можна використати: посилання на джерело внизу статті не є дозволом на фото (за рішенням суду ЄС у справі Renckhoff, перезавантаження чужого фото на свій сервер потребує дозволу). Безпечніше:

- **DVIDS** і **af.mil/News/Photos** (фото військових США, зазвичай публічний домен): на сторінці знімка перевір примітку («IMAGE IS PUBLIC DOMAIN») і автора. Якщо на сторінці видання підпис «U.S. Air Force photo by …», шукай оригінал там, це може бути те саме фото події. Прямий файл на af.mil лежить на `media.defense.gov/…` (правий клік на фото → «Copy image address»); `--image=page` для таких сторінок не спрацює, там немає `og:image`. Правила DVIDS (dvidshub.net/about/copyright): новинне використання дозволене, але публічний домен стосується лише робіт урядовців, а на DVIDS бувають матеріали сторонніх правовласників, тож примітка на сторінці знімка («IMAGE IS PUBLIC DOMAIN») обов'язкова. На сайті має бути дисклеймер про непідтримку (один рядок, наприклад у футері): «The appearance of U.S. Department of War (DoW) visual information does not imply or constitute DoW endorsement.» Фото не використовуй у рекламі й просуванні. У `photoCredit` пиши автора з картки знімка й джерело: `"Jacob Mattingly / DVIDS"`.
- **Вікісховище** з відкритою ліцензією (дотримуйся її умов, зазвичай потрібне авторство).
- Власні фото або ті, на які отримав дозвіл листом.
- Без фото: стоїть заглушка.

Адресу прямого файлу бери правою кнопкою на фото → «Copy image address». Якщо фото не з цієї події, так і напиши в підписі («File photo»).

## Крок 2. Перевірити чернетку

Відкрий файл `drafts/<дата>-<час>-<назва>.md`. Поруч лежить `….source.txt` із текстом, з якого модель робила рерайт: виділи обидва файли в провіднику → Compare Selected.

- **Виділені фрагменти** (жирним, між `**…**`) повторюють джерело: перепиши їх своїми словами і прибери зірочки. Що лишиться, при публікації все одно видалиться, але **тільки якщо в чернетці є рядок `highlights:`**: видалиш його, і справжній жирний у тексті зберігається. Теги `<mark>` зі старих чернеток прибираються завжди.
- **Поля вгорі:** заголовок (кожне слово з великої літери), опис, `subcategory` **або** `isWarInUkraine: true` (рівно одне з двох), теги, `mainPicture` (адреса `res.cloudinary.com`: фото або заглушка).
- **Блок `problems`:** якщо він є, публікація відмовить, поки не виправиш названі поля. `warnings` — підказки, не блокують.
- **Цифри й цитати** звір із `….source.txt`. Прямих цитат у тексті мало: слова людей модель передає непрямою мовою.
- **Автор головного фото** впиши в рядок `photoCredit:` під `mainPicture` (він є в кожній новій чернетці, спочатку порожній). Сайт сам малює на фото, у лівому нижньому куті, `Photo: <те, що ти впишеш>`, тож пиши лише автора або джерело: `"Airbus"`, `"Staff Sgt. Ім'я Прізвище / U.S. Air Force"` або `"Airbus (file photo)"`. До 200 символів, в лапках. Те саме можна зробити командою: `--credit="…"` в `npm start` або в `attach-image`. Власне фото підпису не потребує, тоді лишай порожнім; з чужим фото і порожнім полем `publish-draft` попередить (але не зупинить). Фото між абзацами підписуються самим рядком картинки (`--caption`).

### Картинки, посилання й відео в тексті

Текст статті це Markdown. Модель пише звичайні абзаци, а картинки, посилання й відео додаєш ти. Перед кожним абзацом порожній рядок.

**Поки що сайт малює лише абзаци й звичайні посилання.** Картинки й відео в тексті статей не вставляй: сервер їх прийме, але на сторінці вони виглядатимуть неправильно. Розділи нижче про картинки й відео: на майбутнє.

**Додаткова картинка між абзацами.** Завантаж її на Cloudinary й отримай готовий рядок:

```
npm run upload-image -- <https-адреса або шлях до файлу> --alt="що на фото" --caption="Підпис. Photo: автор"
```

Команда друкує один рядок, який ти вставляєш у чернетку **окремим абзацом** (порожній рядок до й після):

```
![що на фото](https://res.cloudinary.com/…/photo.jpg "Підпис. Photo: автор")
```

- `--alt` (опис для скрінрідера) і `--caption` (підпис з автором) **обов'язкові**: без них у рядку будуть слова `DESCRIBE THE PHOTO` і `CAPTION. Photo: AUTHOR`, і публікація не пройде, поки їх не заміниш.
- Картинок у статті не більше 10, лише з нашого Cloudinary, лише окремими абзацами. Інакше сервер відхилить статтю.
- Уся стаття в `body`, окремих полів для вбудованих картинок немає.

**Посилання:** `[текст](https://адреса)`. Лише `http` і `https`.

**Відео (YouTube):** окремим абзацом посилання, текст якого це підпис: `[Підпис до відео](https://www.youtube.com/watch?v=…)`. Програвач намалює фронт, який поки не готовий: до того часу це буде звичайне посилання.

**Не можна:** HTML-теги (`<…>`), посилання з іншою схемою (`javascript:`, `ftp:`), абзац, розбитий на кілька рядків без порожнього між ними (Markdown склеїть їх в один; чернетка про це попередить).

### Правки українською

Для статті з англійського джерела (чи коли правиш саме англійську чернетку) можеш писати свої правки українською прямо в ній (замість англійського речення чи цілим абзацом, також у заголовку, описі й тегах), а потім:

```
npm run translate -- drafts/<файл чернетки>.md
```

(Українське джерело з `….uk.md`: див. вище.) Перекладаються лише частини з кирилицею, решта чернетки не чіпається. Копія файлу до перекладу лишається поруч (`….pre-translation.md`). У консолі будуть попередження, якщо в перекладі загубились число чи назва, змінилось англійське речення або лишилась кирилиця. Публікація відмовляє, поки в тексті є кирилиця.

### Додати фото до готової чернетки

Забув `--image`? Повторний запуск створив би нову чернетку й ще один платний виклик. Натомість найпростіше:

1. Поклади фото в теку `ingestion/photos/` (перетягни файл у VS Code або з Провідника; формати jpg, png, webp, gif, avif, до 10 МБ).
2. Запусти без аргументів:

```
npm run attach-image
```

Команда бере **найновішу чернетку** (за назвою файлу) і **найновіше фото** з `photos/`, а в консолі пише, які саме. Після успіху фото переїжджає в `photos/used/`, щоб наступна стаття не підхопила його знову.

Те саме з явними аргументами (у будь-якому порядку мінімуму: один або обидва):

```
npm run attach-image -- <файл фото | посилання на фото | page>
npm run attach-image -- drafts/<файл чернетки>.md
npm run attach-image -- drafts/<файл чернетки>.md <файл фото | посилання на фото | page>
```

До будь-якого з варіантів можна додати `--credit="Airbus"`: команда заодно заповнить `photoCredit` у чернетці.

Один аргумент із `.md` на кінці вважається чернеткою, будь-який інший фото. Явно названий файл фото команда не переміщує. Вона завантажує фото на Cloudinary, замінює `mainPicture` у файлі й прибирає застаріле попередження про заглушку. Решта файлу не змінюється, моделі в цьому немає. `page` бере головне фото зі сторінки, з якої зроблено статтю.

## Крок 3. Опублікувати

Пробний запуск (перевіряє правила й дублі на сайті, нічого не відправляє):

```
npm run publish-draft -- drafts/<файл чернетки>.md --dry-run
```

Публікація:

```
npm run publish-draft -- drafts/<файл чернетки>.md
```

Результат: `Published: <slug>`. У файл дописуються `publishedAs` і `publishedOn`, тому той самий файл вдруге не опублікується. Якщо ця стаття (за посиланням на джерело) вже на сайті, публікація зупиниться; свідомо опублікувати все одно: додай `--force`.

## Крок 4. Перевірити на сайті

- Стаття: `http://localhost:3000/<slug>`.
- Розділ: `http://localhost:3000/news/<розділ>` (air, land, naval, cyber, space, uav, ukraine).

## Якщо щось пішло не так

| Повідомлення | Що робити |
|---|---|
| `Unknown source domain: …` / `Refusing to open …: it is not in ALLOWED_SOURCES` | Додай домен у `ALLOWED_SOURCES`. Друге повідомлення означає, що редирект повів на сайт поза списком. |
| `There is already a draft for this link: …` | Відкрий ту чернетку. Створити ще одну свідомо: `--force`. |
| `This article is already on the site: <slug> …` | Статтю вже опубліковано. Якщо все одно треба: `--force`. |
| `Could not check the site for duplicates: …` | Це попередження: сервер недоступний, дублі на сайті не перевірено. Запусти `server` і за потреби повтори. |
| `Not a valid article address` | Перевір посилання. |
| `The page address must start with https://` | Заміни `http://` на `https://`. |
| `The page answered HTTP 403 / 404 …` | Сайт блокує автоматичні запити або адреси не існує. Перевір адресу, інакше режим «вручну». |
| `Only N characters of text were found …` | Схоже на paywall або не статтю. Режим «вручну». |
| `Could not find an article on the page` | Режим «вручну». |
| `No publication date on the page and none given` | Це попередження: допиши дату другим аргументом. |
| `--image=page needs a fetched page that has a picture` | У ручному режимі `--image=page` не працює, дай посилання на фото. |
| `Invalid publication date …` | Дата лише у форматі `YYYY-MM-DD`. |
| `The source is not a usable article: …` | У тексті не стаття (paywall, меню). |
| `The picture was not uploaded, the placeholder is used instead: …` | `Invalid environment`: немає змінних `CLOUDINARY_*`; `403` / `404`: сайт не віддає фото, візьми інше посилання; `not a supported image`: це не jpg, png, webp, gif чи avif. Фото можна додати потім командою `attach-image`. |
| `The Ukrainian rewrite (see the .uk.md file): Too close to the source …` | Український рерайт надто схожий на оригінал: відкрий `….uk.md`, там підсвічено уривки. Перепиши відповідні місця в англійській чернетці. |
| `Translation: …` (попередження) | У перекладі щось не збіглося з оригіналом (число, назва, англійське речення): звір це місце. |
| `The model refused the request` | Повтори пізніше або перевір текст. |
| `Rate limited…`, `Anthropic rejected the API key`, `Bad request: … credit balance …` | Ліміт запитів, ключ або баланс у консолі Anthropic. |
| `Not published: N problem(s)` і рядки `PROBLEM:` | Виправ названі поля у файлі, запусти ще раз. Кирилицю прибери командою `translate`. |
| `body: Every image in the body needs a description / a caption` | У рядку картинки бракує опису в квадратних дужках або підпису в лапках. |
| `body: An image in the body must be a paragraph of its own` | Картинка має стояти окремим абзацом: порожній рядок до й після. |
| `body: …must be an https address on an allowed image host` | Картинка не з нашого Cloudinary: завантаж її командою `upload-image`. |
| `body: An image … still has the placeholder description or caption` | Заміни `DESCRIBE THE PHOTO` і `CAPTION. Photo: AUTHOR` на справжні. |
| `body: Links in the body must start with http:// or https://` / `HTML is not allowed` | Виправ посилання або прибери HTML-тег. |
| `A paragraph is split into several lines` (попередження) | Постав порожній рядок між абзацами, інакше Markdown склеїть рядки. |
| `This draft is already published as …` | Стаття вже на сайті. Щоб повторити свідомо, видали з файлу рядки `publishedAs` і `publishedOn`. |
| `… is a copy kept next to a draft … not a draft itself. Publish … instead` | Ти вказав `….uk.md` або `….pre-translation.md`. Це копії, які лежать поруч із чернеткою (українська версія і текст до перекладу). Публікуй, перекладай і додавай фото лише в основний файл `….md` (команда сама називає його). |
| `Login failed (HTTP 400)` | Перевір `ADMIN_LOGIN` і `ADMIN_PASSWORD` в `ingestion/.env`: вони мають збігатися з адміном у базі (оновити пароль в базі: `npm run prisma:seed` у `server`). |
| `no answer from the server` | Запусти `server` (`npm run start:dev`). |
| `Publishing failed (HTTP 400): …` | Сервер назвав поле, виправ його у файлі. |

## Чого поки немає

- Окреме поле «автор фото» на сервері й під фото на сайті (поки підпис пишеш вручну в кінці тексту).
- Редагувати вже опубліковану статтю (на сервері немає такого ендпоінта: правка через Prisma Studio).
- Обробка списку посилань за один запуск.
